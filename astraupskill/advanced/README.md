# From learning archive to a complete CRUD feature

This route turns IPSKILL's large archive into a sequence of small deliverables. You will first understand the existing React workspace, then build one Contact book feature in a separate practice application. IPSKILL records your work; its completion button does not run or assess that application.

Allow six to eight sessions of 45–90 minutes. These are planning estimates, not deadlines. End a session with one observable result and a short explanation. If setup takes the whole session, record that honestly and resume at the same checkpoint.

Before starting, you should be able to read a TypeScript object, follow a promise that rejects, and explain a controlled React input. If those are unfamiliar, use the corresponding TypeScript and React tracks first. You do not need to finish all six tracks. Choose **React plus Node** or **React plus .NET** for the backend extension; both routes share the same behavioral contract.

1. [Guided route](01-guided-route.md): choose a starting point and produce six concrete artifacts.
2. [Worked state traces](02-worked-traces.md): distinguish form, workspace draft and accepted storage.
3. [Debugging labs](03-debugging-labs.md): reproduce conflicts and inspect rejected changes.
4. [Build exercises](04-build-exercises.md): implement one behavior at a time.
5. [Solutions and rubric](05-solutions-and-rubric.md): compare after attempting the work.
6. [Capstone handoff](06-capstone.md): demonstrate an independently built Contact book.

Keep an evidence notebook with: case ID, starting state, action, predicted result, observed result, relevant file, and remaining uncertainty. Use fictional contacts. A screenshot can show an error message; a database or state assertion is needed to establish that rejected input did not change accepted data.

The local prediction worksheet in [labs](labs/README.md) provides fast feedback on the state model without installing packages. It does not launch React or prove IndexedDB behavior. The existing [verification record](../VERIFICATION.md) remains the source for previously executed application checks.
