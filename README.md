# SQL Dojo

**A self-directed, pytest-graded PostgreSQL course: from your first SELECT
to query-plan tuning.**

48 lessons. Every exercise is real SQL you write yourself against a real
PostgreSQL 16 database seeded with a multi-million-row e-commerce dataset.
An automated gate grades your work and — when you fail — teaches: it shows
the rows it expected, the plan your query produced, the milliseconds it
measured, and points you at what to reread. Nothing autocompletes. Nothing
is multiple-choice.

## Setup (once)

Prerequisites: Docker Desktop, Python 3.11+, [uv](https://docs.astral.sh/uv/).

```bash
uv venv
uv pip install -e ".[dev]"
cp .env.example .env
uv run dojo up          # start PostgreSQL 16 in Docker
uv run dojo seed        # build the template database (~5 minutes, one time)
```

Then:

```bash
uv run dojo next
```

…which will point you at lesson 00. That's the whole onboarding.

## The gameplay loop

1. `uv run dojo next` — tells you what to work on.
2. Read `lessons/<lesson>/README.md`, top to bottom.
3. Edit `lessons/<lesson>/exN/solution.sql` (Part 5 adds `indexes.sql`).
4. `uv run dojo test <lesson> <exN>` — the gate grades you.
5. Red? Read the failure — it's written to teach. Stuck?
   `uv run dojo hint <lesson> <exN>` reveals one hint tier at a time.
6. Green? `uv run dojo next` again.

Every graded run happens against a **fresh, throwaway clone** of the seeded
template. You cannot break anything, ever. Experiment freely in a
persistent sandbox with `uv run dojo lab <lesson>` (psql; `\q` to exit).

## Commands

| command | what it does |
|---|---|
| `dojo up` / `dojo down` | start / stop the database container |
| `dojo seed` | (re)build the template database + `docs/dataset_facts.md` |
| `dojo test <lesson> [ex]` | grade a lesson or a single exercise |
| `dojo hint <lesson> <ex>` | reveal the next hint tier |
| `dojo status` | full progress dashboard |
| `dojo next` | first incomplete exercise, with exact commands |
| `dojo review` / `dojo review run` | list / run due spaced reviews |
| `dojo plan <lesson> [ex]` | EXPLAIN your current solution, no gate (Part 5) |
| `dojo lab <lesson>` | persistent psql sandbox clone (`--clean` drops all labs) |
| `dojo reset-baseline` | forget this machine's speed baselines |
| `dojo verify [lesson]` | author/CI: prove every exercise is solvable |

(Prefix everything with `uv run`, or activate the venv. A `Makefile` with
the same verbs exists for muscle memory.)

## The curriculum

- **Part 0 — Orientation** (00): toolchain, dataset, the loop.
- **Part 1 — SQL fundamentals** (01–12): SELECT, WHERE, ORDER BY,
  expressions, NULL logic, aggregates, GROUP BY, all the joins, set
  operations, and a business-report capstone.
- **Part 2 — Intermediate querying** (13–20): subqueries, CTEs +
  recursion, window functions, pivots, dates, text & JSONB, and an
  analytics capstone.
- **Part 3 — Modifying data** (21–23): INSERT/UPDATE/DELETE, idempotent
  upserts, transactions with an injected mid-flight crash.
- **Part 4 — Schema design** (24–29): types, constraints that bite,
  normalization to 3NF, views, zero-downtime ALTERs, and a design
  capstone graded on properties, not DDL.
- **Part 5 — Performance** (30–46): reading EXPLAIN, then one lesson per
  weapon — B-trees, composites, prefixes, covering indexes, ordered
  indexes, statistics, join algorithms, bitmaps, partial/expression
  indexes, GIN (full-text + JSONB), BRIN, MVCC/VACUUM, partitioning,
  materialized views. Gates check rows, plan shape, **and speed** (≥8x vs
  your machine's own measured baseline).
- **Part 6 — Capstone** (47): a speed target, a live schema change, and a
  diagnose-from-the-plan exercise.

Every lesson has 2–4 required exercises; most have an optional
**challenge**. Parts 1–2 lessons ship a **review variant** that `dojo
review` brings back at growing intervals (3 → 7 → 21 → 60 days) — old
topics stay fresh while you move forward.

## The dataset

50,000 customers, 10,000 products, 500,000 orders, 1M order items, 1M
reviews, 3M clickstream events, and a 500-person staff org chart —
deterministic (fixed seeds, fixed timestamps), so your numbers match the
lessons' numbers on any machine. Tour it in [docs/dataset.md](docs/dataset.md);
exact figures live in [docs/dataset_facts.md](docs/dataset_facts.md),
regenerated by every seed.

## Honesty model

Hints, reference queries (`expected.sql`), and author solutions
(`.reference/`) sit in plain sight in the lesson directories. Nothing is
encrypted — this course belongs to you, and the CLI just makes the honest
path the convenient path: `dojo hint` reveals hints progressively and
notes how many you used (`dojo status` shows it; there's no penalty).
You're here to learn, not to beat a proctor.

## Troubleshooting

- **`Cannot reach PostgreSQL`** — `uv run dojo up`, wait a few seconds
  (healthcheck), retry. Is Docker Desktop running?
- **`Template 'dojo_template' missing`** — `uv run dojo seed`.
- **Hangs connecting on Windows/Docker Desktop** — keep `POSTGRES_HOST=
  127.0.0.1` in `.env`. `localhost` can resolve to IPv6 `::1` and hang.
- **Speed gates feel unfair after a hardware/load change** — `uv run dojo
  reset-baseline` re-measures baselines on the next run. Speed gates
  auto-skip when the baseline is under 2 ms (nothing meaningful to grade).
- **Port 5432 already in use** — change `POSTGRES_PORT` in `.env`; compose
  picks it up.
- **Start truly over** — `docker compose down -v` (deletes the data
  volume), then `dojo up` + `dojo seed`. Progress lives in
  `data/progress.json`; delete it to reset the dashboard too.
