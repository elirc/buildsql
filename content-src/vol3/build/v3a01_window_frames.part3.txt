WITH daily AS (
    SELECT date_trunc('day', created_at)::date AS day,

    FROM orders
    WHERE created_at >= '2023-10-01'
      AND created_at <  '2023-11-01'
    GROUP BY 1
)

                          ROWS BETWEEN 1 FOLLOWING

SELECT id,

## Exercise 7 — GROUPS and EXCLUDE

Edit `ex7/solution.sql`.

Works against `staff(id int, name text, department text, manager_id int,
salary numeric(10,2), hired_on date)`, restricted to `finance` (61 rows).

Compensation is reviewing salary *bands*. Band each person by rounding their
salary to the nearest ten thousand — `round(salary, -4)`, a negative scale
rounding to the left of the decimal point — then, for each person, report
how many colleagues sit in their band and the bands immediately either side
of it, and how many sit in those neighbouring bands alone.

This is what `GROUPS` mode is for. `ROWS BETWEEN 1 PRECEDING AND 1
FOLLOWING` would give you three arbitrary rows; `GROUPS BETWEEN 1 PRECEDING
AND 1 FOLLOWING` gives you three peer groups, however many rows each one
holds.

Illustration with three bands holding 2, 3 and 1 people:

```
 id | salary   | band  | band_and_neighbours | neighbours_only
----+----------+-------+---------------------+----------------
  3 | 51000.00 | 50000 |                   5 |               3
  8 | 48000.00 | 50000 |                   5 |               3
  1 | 62000.00 | 60000 |                   6 |               3
  5 | 57000.00 | 60000 |                   6 |               3
  9 | 61000.00 | 60000 |                   6 |               3
  2 | 72000.00 | 70000 |                   4 |               3
```

The people in band 60000 see all six rows (2 + 3 + 1). The people in band
50000 see five, because there is no band below them. `neighbours_only` is
the same frame with the person's own band removed — `EXCLUDE GROUP`, not
`EXCLUDE TIES`, which would keep the person and drop only their
band-mates.

Columns, in this order: `id`, `name`, `salary`, `band` (`round(salary, -4)`),
`band_and_neighbours`, `neighbours_only`.

**Ordered by `band` ascending, then `id` ascending.** (61 rows.)

-- v3a01_window_frames / ex7 — GROUPS mode over salary bands, with EXCLUDE.
SELECT id,
       name,
       salary,
       round(salary, -4)      AS band,
       count(*) OVER w        AS band_and_neighbours,
       count(*) OVER w_others AS neighbours_only
FROM staff
WHERE department = 'finance'

             GROUPS BETWEEN 1 PRECEDING AND 1 FOLLOWING),

                    GROUPS BETWEEN 1 PRECEDING AND 1 FOLLOWING

WITH fin AS (
    SELECT id, name, salary, round(salary, -4) AS band
    FROM staff
    WHERE department = 'finance'
),
bands AS (
    SELECT band,
           count(*)                          AS n,
           dense_rank() OVER (ORDER BY band)  AS r
    FROM fin
    GROUP BY band
)
SELECT f.id,
       f.name,
       f.salary,
       f.band,
       (SELECT coalesce(sum(x.n), 0)::bigint
          FROM bands x
         WHERE x.r BETWEEN b.r - 1 AND b.r + 1)      AS band_and_neighbours,
       (SELECT coalesce(sum(x.n), 0)::bigint
          FROM bands x
         WHERE x.r BETWEEN b.r - 1 AND b.r + 1
           AND x.r <> b.r)                           AS neighbours_only
FROM fin f
JOIN bands b ON b.band = f.band
ORDER BY f.band, f.id;

## Exercise 8 — a named window and the last_value trap

Edit `ex8/solution.sql`.

Works against `orders(id int, customer_id int, status text, total
numeric(10,2), created_at timestamptz)`, October 2023 only
(`created_at >= '2023-10-01' AND created_at < '2023-11-01'`), rolled up to
one row per day.

The month-end pack wants every daily row to carry three facts about the
whole month: what the first day brought in, what the last day brought in,
and what share of the month this day was. All three come from one window,
and that window must be able to see the entire partition — including rows
that come *after* the current one.

Illustration on four days:

```
    day     | revenue | first_day_revenue | last_day_revenue | pct_of_month
------------+---------+-------------------+------------------+-------------
 2023-10-01 |  100.00 |            100.00 |           400.00 |        10.00
 2023-10-02 |  200.00 |            100.00 |           400.00 |        20.00
 2023-10-03 |  300.00 |            100.00 |           400.00 |        30.00
 2023-10-04 |  400.00 |            100.00 |           400.00 |        40.00
```

`last_day_revenue` is 400.00 on **every** row. If yours equals `revenue` on
every row, you have met the most famous bug in window functions: the default
frame ends at the current row, so the last value in it is the current row.
`first_value` hides the problem by being accidentally correct.

Declare the window once in a `WINDOW` clause and use it three times.

Columns, in this order: `day` (a `date`), `revenue`, `first_day_revenue`,
`last_day_revenue`, `pct_of_month` (100 × this day's revenue ÷ the month's
revenue, rounded to 2 decimals).

## Hint 1

Write the naive version first, deliberately:


## Hint 2

The explanation: with an `ORDER BY` and no frame clause, the frame is `RANGE

## Hint 3

There are two repairs. One extends the frame to `UNBOUNDED FOLLOWING`. The

@@@FILE ex8/solution.sql
-- v3a01_window_frames / ex8 — one named window, three whole-partition facts.
WITH daily AS (
    SELECT date_trunc('day', created_at)::date AS day,
           sum(total)                          AS revenue
    FROM orders
    WHERE created_at >= '2023-10-01'
      AND created_at <  '2023-11-01'
    GROUP BY 1
)
SELECT day,
       revenue,
       first_value(revenue) OVER month_w AS first_day_revenue,
       last_value(revenue)  OVER month_w AS last_day_revenue,
       round(100 * revenue / sum(revenue) OVER month_w, 2) AS pct_of_month
FROM daily
WINDOW month_w AS (ORDER BY day
                   ROWS BETWEEN UNBOUNDED PRECEDING
                            AND UNBOUNDED FOLLOWING)
ORDER BY day;

    SELECT date_trunc('day', created_at)::date AS day,
           status,
           sum(total)                          AS revenue

The numerator changes on every row; the denominator does not. Two different

## Hint 2

You have written both halves before. The cumulative half is an ordered

## Hint 3

@@@FILE review1/solution.sql
-- v3a01_window_frames / review1 — cumulative share of the ops payroll.
SELECT id,
       name,
       salary,
       round(100 * sum(salary) OVER (ORDER BY salary DESC, id)
                 / sum(salary) OVER (), 2) AS cum_pct_of_payroll
FROM staff
WHERE department = 'ops'
ORDER BY salary DESC, id;

WITH ops AS (
    SELECT id, name, salary
    FROM staff
    WHERE department = 'ops'
),
payroll AS (
    SELECT sum(salary) AS total FROM ops
)
SELECT o.id,
       o.name,
       o.salary,
       round(100 * (SELECT sum(x.salary)
                      FROM ops x
                     WHERE x.salary > o.salary
                        OR (x.salary = o.salary AND x.id <= o.id))
                 / p.total, 2) AS cum_pct_of_payroll
